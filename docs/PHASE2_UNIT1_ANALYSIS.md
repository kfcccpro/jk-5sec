## 2. 저자식 핵심 규칙

### Rule A. 문장에 필요한 본동사 개수

- 기본 문장에는 본동사 1개가 필요하다.
- 접속사 또는 관계사가 절을 하나 추가할 때마다 본동사도 하나 더 필요하다.
- 따라서 기본 판단식은 다음과 같다.

`필요한 본동사 수 = 절을 연결하는 접속사·관계사 수 + 1`

### Rule B. 먼저 '자리'를 판정한다

문제의 빈칸 또는 선택지 자리가 본동사 자리인지 준동사 자리인지 먼저 판정한다.

1. 이미 있는 본동사를 센다.
2. 접속사·관계사를 센다.
3. 생략된 관계사도 필요한 경우 계산에 포함한다.
4. 필요한 본동사 수와 실제 본동사 수를 비교한다.
5. 본동사가 부족하면 본동사 형태를, 이미 충족되면 준동사 형태를 우선 검토한다.

### Rule C. 접속사처럼 보이는 단어를 무조건 세지 않는다

`and`, `or`, `as` 등은 앞뒤에 절을 연결하여 동사가 실제로 추가될 때만 본 판단식의 연결 요소로 센다. 단순 명사·구 연결이면 별도의 절 추가로 보지 않는다.

### Rule D. 삽입 표현은 핵심 문장 골격에서 분리한다

대시나 쉼표로 삽입된 표현은 핵심 절 구조를 먼저 잡을 때 별도 층으로 처리한다. 학습자는 우선 핵심 문장 골격의 본동사와 연결어를 판정하고, 삽입부는 두 번째 단계에서 확인한다.

## 3. 앱용 5초 판단 순서

학생에게 문법 설명을 먼저 보여주지 않는다.

1. **답 선택** - Cold Attempt
2. **본동사 찾기** - 문장 안에서 실제 본동사만 탭
3. **연결어 찾기** - 접속사·관계사 또는 생략 관계사 위치 판단
4. **개수 비교** - `연결어 수 + 1`과 실제 본동사 수 비교
5. **자리 결론** - 본동사 자리 / 준동사 자리
6. **원문 재도전** - 처음 선택지로 복귀

정답을 맞혀도 2-5단계 근거가 틀리면 `불안정 정답`으로 기록한다.

## 4. UNIT 1 확인문제 구조 분석

원문 전체 문장은 Public 저장소에 넣지 않고 구조값만 기록한다.

### Q1

- 선택: `increases / increasing`
- 정답: `increasing`
- 핵심 본동사: `requires`
- 절 연결어 수: 0
- 필요한 본동사 수: 1
- 이미 본동사 수 충족
- 결론: 빈칸은 준동사 자리
- 오류 코드: `ADDED_EXTRA_FINITE_VERB`

### Q2

- 선택: `leave / leaving`
- 정답: `leaving`
- 핵심 본동사: `eat`, `kill`
- 생략 관계사: 1개로 계산
- 필요한 본동사 수: 2
- 실제 본동사 수: 2
- 결론: 빈칸은 준동사 자리
- 오류 코드: `MISSED_OMITTED_RELATIVE`

### Q3

- 선택: `it / which`
- 정답: `it`
- 연결 구조: `when` + `that`
- 실제 본동사: `inherited`, `was`, `would continue`
- 필요한 본동사 수: 3
- `which`를 추가하면 연결 절 수가 불필요하게 늘어난다.
- 결론: 관계사 `which`가 아니라 대명사 `it`
- 오류 코드: `OVERCOUNTED_RELATIVE_CLAUSE`

### Q4

- 선택: `have / having`
- 정답: `having`
- 핵심 판단에서는 삽입 표현을 분리한다.
- 핵심 연결어: `when`
- 핵심 본동사: `find`, `will be`
- 필요한 본동사 수: 2
- 실제 본동사 수: 2
- 결론: 빈칸은 준동사 자리
- 오류 코드: `FAILED_TO_IGNORE_INSERTION`

### Q5

- 선택: `have / having`
- 정답: `have`
- 절 연결어: 0
- 기존 본동사: 0
- 필요한 본동사 수: 1
- 결론: 빈칸은 본동사 자리
- 오류 코드: `MISSED_REQUIRED_FINITE_VERB`

## 5. 학습 상태 판정

한 문제의 결과는 단순 O/X가 아니라 다음 네 상태로 저장한다.

- `MASTERED_NOW`: 정답 + 근거판단 모두 정확
- `CORRECT_UNSTABLE`: 정답은 맞지만 근거가 틀림
- `REPAIRED`: 최초 오답 후 교정과 원문 재도전 성공
- `UNRESOLVED`: 교정 후에도 원문 재도전 실패
